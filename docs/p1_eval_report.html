延迟分布对比

延迟暴涨原因：P0 使用 Ollama Q4 量化推理（GPU offload），P1 使用 transformers CPU bfloat16 推理。 这不是模型能力问题，而是推理引擎差异。GGUF 转换 + Ollama 部署后延迟应恢复到 2-5s 水平。

分析与结论

微调效果

关键词命中率提升 26.8%（18.3% → 23.2%），说明 LoRA 微调有效提升了模型的中医知识表达能力和回答准确性。

分类表现分析

类别分析
方剂查询 最大亮点：65.5% → 84.3%（+28.7%）。微调后模型对核心方剂组成记忆显著增强，如桂枝汤、麻黄汤、大承气汤等回答更准确。
经典解释 提升最大（相对）：3.3% → 8.3%（+150%）。微调后模型对六经辨证等概念解释更到位，但绝对值仍低，需更多解释类训练数据。
综合问答 18.7% → 22.2%（+18.7%）。方剂比较类问题回答结构更完整，但细节错误仍多（如大柴胡汤组成遗漏大黄）。
经典原文检索 1.56% → 1.82%（+16.7%）。微调未解决核心问题——检索系统未变，recall@5 仍只有 5.4%，模型拿不到正确原文。
药材关联 唯一下降：10.9% → 9.5%（-13.1%）。推测原因：微调数据中药材关联类仅 209 条（17.7%），占比偏低；且药材-方剂关系查询需要图谱支持而非生成。

关键发现

  • 检索是最大瓶颈：recall@5 = 5.4% 持平 P0，因为 P1 只微调了生成模型，检索器（ChromaDB + bge-small-zh）未变。50 题中 47 题检索结果不包含正确答案条目。
  • 生成质量有明显提升：即使检索结果相同，P1 的回答比 P0 更准确、更简洁。典型改善：方剂组成不再编造剂量，回答结构更清晰。
  • 幻觉仍严重：原文检索类问题中，模型仍会编造不存在的伤寒论条文（如将第12条说成麻黄汤主之），1.5B 模型能力上限明显。
  • 重复生成问题：部分长文本生成出现重复循环（如 Q5、Q8），P0 也有此问题但 P1 更频繁，可能与 LoRA 微调加剧了某些 token 的偏好有关。
  • 延迟差异是引擎问题：P0 用 Ollama Q4（GPU），P1 用 transformers bfloat16（CPU）。GGUF 转换后应恢复。
