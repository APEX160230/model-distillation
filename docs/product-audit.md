## 二、P0 阻断问题（必须修复才能称"产品级"）

### P0-1: SFT 数据来源与 PRD 严重偏离

**PRD 承诺** (§4.2): 倪海厦讲稿 PDF → SFT 训练集 → LoRA 微调学说话方式
**实际实现**: SFT 数据 1179 条来自 `formulas_db.py`（结构化方剂数据库），不是从 PDF 讲稿提取

**影响链**:
1. 训练数据是"方剂知识问答"，不是"倪师口语化讲解"
2. LoRA 学到的是方剂知识，不是说话风格
3. PRD §1.2 P1 验收标准"风格相似度≥0.7"从未测量——因为根本没有风格数据可测
4. PRD §13.3"隐式风格迁移"的核心价值主张落空

**根因**: PDF 提取只做了伤寒论 1 本（330 条原文），倪海厦 5 本讲稿 PDF 从未被提取为 SFT 数据。`sft_generate.py` 是用代码规则从 `formulas_db` 生成的指令对，与 PDF 讲稿无关。

### P0-2: 风格迁移从未验证

**PRD 要求** (§1.2): "LoRA 微调后回答具有倪师讲解风格（人评通过率≥60%）" + "风格相似度（embedding 余弦相似度≥0.7）"
**实际**: 两项指标均未实现

- 风格相似度：需要倪师原文做基准，但倪师讲稿从未提取
- 人评通过率：从未组织盲测
- P1 评测只测了 keyword_accuracy（+27%）和 recall@5（持平），风格维度零数据

**影响**: 无法回答"LoRA 微调到底有没有学到倪师风格"这个核心问题。P1 阶段的验收标准实际上未完成。

### P0-3: CI/CD 完全缺失

**PRD 要求** (§14): GitHub Actions, 4 类测试（单元/冒烟/脚本校验/集成）
**实际**: `.github/` 目录不存在

- 68 个单元测试存在但不会自动运行
- push/PR 无任何检查
- 训练脚本无冒烟测试
- 无集成测试
- 无代码质量检查（ruff/mypy）

**影响**: 代码可随时被破坏而不自知。对一个标榜"产品级"的项目，零 CI 是不可接受的。

### P0-4: 生成内容安全护栏缺失

**PRD §2.3 能力边界**: "不诊断具体病人的病情"、"不开处方"
**实际**: 系统会自信地输出**医学错误的方剂推荐**

具体案例（P2.2 真实用户评测）:
- Q5: 用户问"肚子痛拉肚子手脚凉"→ 检索到少阴寒化证条文（295/29/317），概念简述正确，但模型推荐"白虎加人参汤"——这是治阳明热证的反方向方剂，对少阴寒化证属于**禁忌**
- Q7: 概念简述说"太阳伤寒证"（表实），模型却说"表虚证"——**事实错误**
- Q8: "发烧拉肚子"→ 推荐"大承气汤"——**完全错误**

**影响**: 虽然定位是"知识检索"不是"问诊"，但系统输出"用什么方"这类直接建议时，错误推荐可能误导用户。PRD §13.4 说"检索为空时返回提示而非生成"，但检索不为空时模型生成错误信息没有兜底。

## 三、P1 重要问题（影响产品质量但非阻断）

### P1-1: 内容覆盖不完整

| 数据 | PRD 要求 | 实际 | 缺口 |
|------|---------|------|------|
| 伤寒论条文 | 397 条 | 330 条 | -67 条 (17%) |
| 知识图谱方剂 | 113 首 | 71 首 | -42 首 (37%) |
| PDF 提取 | 5 本 | 1 本 | -4 本 (80%) |

### P1-2: LLM Judge 不可靠

用 qwen2.5:1.5b 同时做生成器和裁判——裁判能力等于或弱于被裁判者。

- Q1-4: judge 直接 timeout / 解析失败（judge_score=-1）
- Q5: judge 给 2.5 分，但实际错误程度应给 1 分以下
- 系统性偏高/偏低无法检测

PRD §FR9 未指定 judge 模型，但产品级评测要求 judge 能力 >> 被评模型。

### P1-3: README 项目状态过时

README 仍标记 P1/P2 为"训练中/未完成"，实际全部已完成。对外部访客造成误导。

### P1-4: Dockerfile 依赖与 pyproject.toml 不同步

Dockerfile 手动列出依赖包，没有用 `pip install -e ".[serve,rag]"`，pyproject.toml 改了依赖后 Docker 镜像不会更新。

### P1-5: 真实用户 keyword_accuracy 极低 (16.54%)

模板评测 keyword_accuracy=72%，真实用户评测 16.54%——差距巨大。说明模型在自然语言场景下的回答质量远低于学术问法。LLM judge 3.17/5 也只是勉强及格。

## 五、根因分析

### 为什么 SFT 数据来源偏离 PRD？

1. PDF 提取只验证了伤寒论 1 本（可行性验证阶段只测了这本）
2. 倪海厦讲稿 PDF 的文本结构复杂（讲稿 vs 教材混杂），提取为 instruction-output 对需要大量 NLP 工作
3. 用 `formulas_db` 生成 SFT 数据是"快速跑通训练流水线"的捷径，但偷换了数据来源
4. 一旦训练跑通、Ollama 部署成功，注意力转向了 RAG 检索优化，SFT 数据来源问题被搁置

### 为什么风格迁移从未评测？

1. 风格评测需要倪师原文做基准——而讲稿未被提取
2. embedding 余弦相似度需要额外实现——被 LLM-as-judge 替代了
3. 人评需要盲测组织——练手项目无此条件
4. P1 评测用 keyword_accuracy 替代了风格评测，但这是不同维度

### 为什么 CI 缺失？

1. PRD §14 写了 CI 要求但实现时优先级被降低
2. GitHub Actions 配置在项目结构 §9 中列出但从未创建
3. 测试文件存在但从未被 CI 触发验证
