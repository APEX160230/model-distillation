## 1. 概述

### 1.1 背景

上司给定项目目标：输入倪海厦医案（神农本草经、针灸、黄帝内经、伤寒论等），输出部署在网站上的倪师问答；技术路线为端侧模型微调 + RAG 知识库；部署在 2 核 4G 服务器；配合微信公众号宣传。

用户附加的核心诉求（口头要求）：**「我告诉他哪里不舒服，他能给些建议」**。

v2.2 实现了「知识检索与理解」，但经真实使用评估（2026-08-12 严谨性评测 + 用户试用）确认：知识问答类能力与搜索引擎重合，缺乏实际意义。本项目重新定位为**倪师辨证建议助手**——用户描述不适，系统给出辨证方向判断、类方思路轻提示、倪师讲解与就医引导。

### 1.2 目标

| 优先级 | 目标 | 验收方式 |
|---|---|---|
| P0 | 跑通「口语症状描述 → 三层回答」端到端 | 真实症状场景实测，回答结构完整 |
| P0 | 辨证判定不依赖模型推理（图谱数据驱动） | 判定结果可解释，图谱可校验 |
| P0 | 无致命错误：不编方剂、不给剂量、不落危象 | 15-20 例真实场景实测，致命错误 = 0 |
| P1 | 常见六经证型粗粒度辨证方向可靠 | 辨证方向正确率 ≥ 80%（人工判断） |
| P1 | 部署到 2 核 4G 服务器，Web 可对话 | 流式响应，延迟可接受（沿用现有基线） |

### 1.3 范围

**包含：**

- 概念映射层（口语症状 → 中医术语）
- 症状 → 证型映射表建设（人工校验，分层覆盖）
- 辨证图谱重建（复用 113 方 / 20 证型 / 89 条文现成数据，新增症状节点层）
- 辨证判定引擎（症状交集投票 + 关键鉴别追问）
- 倪师讲稿向量库（5 本 PDF 原文，作为讲解与调理素材）
- 三层回答生成（1.5B 仅组织语言，不参与推理）
- 安全护栏（沿用已有 + 追问与低置信拒答）
- Web 前端改造（症状输入 + 三层回答卡片）
- 倪海厦医案调研与接入（相似案例参考，可选）

**不包含：**

- 治未病 / 养生调理建议（1.5B 无法承载，见 §2.3 锚点理论，留后门）
- 开方、给药、剂量（硬边界）
- 精细辨证（无脉象舌象，模糊主诉只能给方向 + 引导就医）
- 多用户平台化（单用户部署）
- 公众号文章（暂缓，不规划）
- 严格里程碑排期（按「数据 → 引擎 → 服务 → 实测」自然推进，随时调整）

### 1.4 术语表

| 术语 | 说明 |
|---|---|
| 概念映射 | 口语症状到中医术语的映射表，如「怕冷」→「恶寒」 |
| 证型 | 中医辨证分型，如太阳中风、太阳伤寒、少阳证 |
| 类方 | 同一治法方向的方剂家族，如「桂枝汤类方」「麻黄汤类方」 |
| 锚点 | 生成内容的可校验出处（图谱结论、条文编号、映射表），防幻觉的物理保障 |
| 辨证员 | 图谱查询模块，负责症状 → 证型判定，不靠模型推理 |
| 讲解员 | 1.5B 模型，仅负责把辨证结论与检索素材组织成倪师口吻的人话 |
| 保安 | 护栏模块，负责剂量/处方/危象拦截、编号校验、拒答 |

## 2. 产品定位

### 2.1 核心场景

用户在 Web 界面输入身体不适描述（自然语言），系统经「概念映射 → 图谱辨证 + 向量检索 → 上下文拼接 → 1.5B 组织 → 护栏校验」流程，返回三层结构的回答。

**典型问答示例：**

> **用户**：我这两天头痛，怕冷，不出汗。
>
> **助手**：
>
> **【辨证方向】** 初步判断偏「太阳伤寒」方向。依据：您提到怕冷（恶寒）、无汗、头痛——这三个症状同时指向太阳伤寒，与伤寒论「太阳病，头痛发热，身疼腰痛，骨节疼痛，恶风无汗而喘者」的方向一致。
>
> **【类方思路】** 传统上这类情况多从「麻黄汤类方」思路考虑（仅作中医知识参考，不构成用药建议）。
>
> **【倪师讲解与就医引导】** 倪师讲稿节选：……（原文引用）。生活上注意保暖、喝温热的水、早点休息。⚠️ 若出现高热不退、胸闷气促等情况，请及时就医。本内容仅供中医知识学习参考，不构成诊疗建议。

### 2.2 三层回答结构

| 层级 | 内容 | 来源 | 是否经模型自由生成 |
|---|---|---|---|
| 第一层 | 辨证方向 + 依据 | 图谱辨证判定 | 否（图谱结论） |
| 第二层 | 类方思路轻提示 | 图谱证型 → 类方标签 | 否（图谱给，无组成无剂量） |
| 第三层 | 倪师讲解 + 生活调理 + 就医引导 | 向量检索讲稿原文 + 护栏模板 | 部分（讲解组织） |

### 2.3 能力边界（锚点理论）

**核心原则：1.5B 模型负责的每个生成环节，其内容必须有可校验的锚点。** 有锚点则模型只是「翻译」，可靠；无锚点则模型自由发挥，必然幻觉。

| 环节 | 锚点 | 判定 |
|---|---|---|
| 理解症状 | 概念映射表（硬数据） | ✅ 可靠 |
| 辨证判定 | 图谱结论（可解释、可校验） | ✅ 可靠 |
| 类方轻提示 | 图谱证型 → 类方标签 | ✅ 可靠 |
| 讲解组织 | 向量检索原文片段 + 条文编号校验 | ✅ 可靠 |
| 调理建议具体内容 | 无同等强度锚点（素材经模型组织时会被加料） | ❌ 不可靠 |

**由此推出的边界决策：**

- 只做「治已病」单入口（用户描述不适 → 建议），不做「治未病」（养生调理）——调理具体建议缺乏校验锚点，1.5B 会自由加料、变成「正确的废话」。留后门：若未来换 7B 模型或积累大量调理 SFT 数据，再考虑。
- 方剂只给「类方思路」标签级提示（如「多从麻黄汤类方考虑」），不给组成、不给剂量、不开方——方剂即处方，1.5B 无法严谨处理。
- 图谱覆盖范围即系统能力范围：图谱没有的场景 → 明确拒答 + 就医引导，绝不硬编。

### 2.4 目标用户

- 想了解中医辨证思路、想学倪师六经辨证的人
- 身体不适、想先了解「大概是什么方向」再决定是否就医的人
- 练手项目定位：Apex 本人 + 导师 + 公众号读者

| 层 | 场景数 | 映射质量 | 目的 |
|---|---|---|---|
| 核心层 | 15-20 个高频场景（感冒类、头痛、咳嗽、胃痛、腹泻、便秘、失眠、月经不调、腰酸、水肿等） | 每场景 3-6 条症状组合，人工逐条校验 | 保证质量 |

## 5. 功能需求

### FR1：概念映射（输入理解）

**输入**：用户口语症状描述。

**处理流程：**

| 步骤 | 说明 |
|---|---|
| 1. 分词/关键词提取 | jieba 分词 + 症状词表匹配（沿用现有 concept_mapper 扩展） |
| 2. 口语 → 术语 | 映射表归一化（怕冷 → 恶寒） |
| 3. 症状集合输出 | 供辨证引擎使用 |

**验收**：常见口语表达 80% 以上能归一化到标准术语；未命中词不阻塞，进入向量检索兜底。

### FR2：辨证图谱重建

**输入**：formulas_data.py 现成数据 + 新增症状映射。

**图谱 schema（v3.0）：**

```
节点类型：
  - Formula（方剂）：113 方（现成）
  - Herb（药材）：组成（现成）
  - Syndrome（证型）：20 证型（现成，可扩展）
  - Symptom（症状）：新增，200+ 术语节点
  - Text（条文）：89 条文（现成）

边类型：
  - CONTAINS（方剂→药材）：现成
  - TREATS（证型→方剂）：现成
  - DERIVED_FROM（方剂→方剂）：22 条加减（现成）
  - MENTIONS（条文→方剂）：现成
  - INDICATES（症状→证型）：新增（SYMPTOM_SYNDROME 映射表）
```

**必做修复：**

- graph_rag.py `query_by_syndrome` 的 `seen_clause` 拼写错误（应为 `seen_clauses`，调用必崩 NameError，现仅被 concept_mapper 前置拦截掩盖）
- 启用 kg_build.py 的 113 方完整图谱（现为死代码，线上仅 71 方精简版）

**验收**：图谱节点 ≥ 400（113 方 + 80 药 + 30 证型 + 200 症状 + 条文）；症状 → 证型 → 类方 → 条文多跳可查；加载 < 100 ms。

### FR3：辨证判定引擎

**输入**：归一化症状集合 S。

**判定逻辑：**

```
1. 对每个症状 s ∈ S，查询图谱 INDICATES 边 → 候选证型集合 T(s)
2. 投票：证型 t 得分 = |{ s | t ∈ T(s) }|（命中症状数）
3. 判定规则：
   - 最高分 ≥ 2 且显著高于次高分 → 判定该证型
   - 最高分 = 1 或与次高分并列 → 触发关键鉴别追问（如「有汗吗？怕冷还是怕热？」）
   - 无命中 → 低置信拒答：「这个情况我不太确定，建议咨询中医师 + 就医引导」
4. 关键鉴别：若缺失「有汗/无汗」「恶寒/恶热」等鉴别点且候选证型在此处分叉 → 优先追问
```

**验收**：典型六经证型（太阳伤寒/中风、少阳、阳明、太阴、少阴）判定正确；追问逻辑不循环（最多 2 轮）。

### FR4：讲稿向量库

**输入**：人纪 5 本 PDF 清洗文本。

**处理流程：**

| 步骤 | 说明 |
|---|---|
| 1. 分块 | 按自然段落/条辨切分，100-300 字/块 |
| 2. 标注来源 | 每块记录 {book, 章节}，便于引用溯源 |
| 3. 向量化 + 入库 | bge-small-zh-v1.5 → ChromaDB（沿用 build_chroma.py 基建，扩展数据源） |
| 4. 素材标签 | 讲解类 / 调理类（为第三层回答筛选素材） |

**验收**：5 本 PDF 全量入库；检索延迟 < 50 ms；「恶寒无汗头痛」类查询能命中太阳伤寒相关讲解。

### FR5：三层回答生成

**输入**：辨证引擎结论 + 向量检索素材。

**上下文拼接与生成：**

```
SYSTEM_PROMPT（强化版）：
你是一位中医老师，擅长用通俗易懂的方式讲解中医经典。
请严格按照给定结构回答，结构为三层：
① 辨证方向：只能引用系统给出的辨证结论，说明依据（哪些症状指向）
② 类方思路：只能引用系统给出的类方标签，加「仅作知识参考」
③ 讲解与引导：引用检索到的倪师讲稿原文（标注条文编号/出处），
   补充生活调理要点与就医引导
严禁：编造方剂组成、给出剂量、开具处方、编造条文编号
若系统未给出辨证结论，明说「不确定」并引导就医。
```

**输出约束：** 单轮回答 ≤ 600 字；max_tokens 上限；流式输出。

**验收**：三层结构遵从率 ≥ 80%（1.5B 实测，不达标则补一轮结构微调，见 §10 风险）。

### FR6：安全护栏（沿用 + 强化）

| 护栏 | 现状 | v3.0 强化 |
|---|---|---|
| 剂量/处方拦截 | ✅ 已有 | 不变 |
| 危象就医引导 | ✅ 已有 | 补充危急症状词表 |
| 条文编号校验 | ✅ 已有 | 不变 |
| 输出侧过滤 | ✅ 已有 | 不变 |
| 检索空拒答 | ✅ 已有 | 不变 |
| 低置信辨证拒答 | ❌ | 新增（FR3 判定逻辑触发） |
| 追问逻辑 | ❌ | 新增（FR3 鉴别规则触发） |

### FR7：Web 服务与前端

**API（沿用 + 微调）：**

| 接口 | 方法 | 说明 |
|---|---|---|

## 6. 系统架构

```
用户输入「我这两天头痛，怕冷，不出汗」
  │
  ▼
概念映射（口语 → 术语：怕冷→恶寒、不出汗→无汗）
  │
  ▼
辨证引擎（图谱 INDICATES 投票）
  ├─ 证据充足 → 证型结论（太阳伤寒方向）+ 类方标签（麻黄汤类方）
  ├─ 证据不足 → 关键鉴别追问（有汗/无汗？）→ 前端选择题
  └─ 无命中 → 低置信拒答 + 就医引导
  │
  ▼
向量检索（讲稿原文：太阳伤寒相关讲解 + 调理素材）
  │
  ▼
上下文拼接（辨证结论 + 类方标签 + 原文片段）
  │
  ▼
1.5B 讲解员（Ollama，只组织语言，不推理辨证）
  │
  ▼
保安护栏（剂量/处方/危象拦截、编号校验、输出过滤）
  │
  ▼
三层回答输出（SSE 流式）
```

### 模块边界

| 模块 | 输入 | 输出 | 职责 |
|---|---|---|---|
| concept_mapper | 口语症状文本 | 归一化症状集合 | 输入理解 |
| diagnosis_engine | 症状集合 | 证型结论 / 追问 / 拒答 | 辨证判定（图谱驱动） |
| kg_build | formulas_data + symptom_mapping | knowledge_graph.json | 图谱构建（启用 113 方） |
| rag_index | 5 本 PDF 文本 | chroma_db/ | 讲稿向量库 |
| generate | 拼接上下文 | 三层回答 | 1.5B 组织语言 |
| guards | 生成结果 | 校验后结果 | 安全护栏 |

## 7. 验证策略（真实使用为准）

沿用 2026-08-12 决策：**评测集降级为开发辅助，防止回归；验收以真实使用为准。**

**真实场景实测：**

- 构造 15-20 例真实症状描述（来自用户视角：头痛、咳嗽、胃痛、拉肚子、失眠、月经不调、手脚冰凉等）
- 人工逐例检查三个维度：
  1. 辨证方向是否正确（图谱结论是否符合常识）
  2. 是否越界（编方剂 / 给剂量 / 开方）
  3. 危象是否拦截、拒答是否恰当
- 及格线：致命错误 = 0；辨证方向错误率 < 20%；结构遵从率 > 80%

**开发辅助评测（防回归）：** 沿用 15 题严谨性评测集 + 50 题知识问答集，跑通不倒退即可，不作为验收依据。
