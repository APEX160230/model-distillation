## 1. 验证背景

在确定路线③（LoRA + GraphRAG）作为技术方案后，识别出两个 P0 级风险需要在投入全面开发前消除：

| 风险编号 | 描述 | 等级 | 验证方式 |
|---------|------|------|---------|
| P0-1 | 中医 PDF 文本提取质量不可控（古文 OCR 大坑） | P0 | Day 1: 下载真实 PDF，提取并量化质量 |
| P0-2 | 知识图谱查询性能不确定（NetworkX 能否满足要求） | P0 | Day 2: 构建迷你图谱，跑查询测试 |

## 2. Day 1: PDF 文本提取质量验证

### 2.1 验证方法

1. 从 qhsxzh.com 下载《人纪·伤寒》PDF（倪海厦讲稿）
2. 分别用 PyMuPDF 和 pdfplumber 提取文本
3. 对比提取质量，量化关键指标

### 2.2 数据源

| 来源 | URL | 内容 | 获取状态 |
|------|-----|------|---------|
| qhsxzh.com | `https://www.qhsxzh.com/wp-content/uploads/2026/05/人纪04伤寒2026.4.pdf` | 人纪04伤寒 PDF | 已下载 |
| 维基文库 | `https://zh.wikisource.org/zh/傷寒論` | 伤寒论原文（公版） | 已获取 |
| nihaixia.org | 百度网盘提取码 7p8t | 完整资料包 13 文件 | 已确认可用 |

### 2.3 提取结果

| 指标 | PyMuPDF | pdfplumber |
|------|---------|-----------|
| 采样页数 | 5 | 5 |
| 总字符数 | 11,769 | 12,357 |
| 平均字符/页 | 2,354 | 2,471 |
| 中医关键词命中 | 17/17 (100%) | 未测 |
| 乱码率 | 0.05% | 未测 |
| 判定 | **PASS** | — |

### 2.4 PDF 基本信息

- **文件名**: 人纪04伤寒.pdf
- **大小**: 13.6 MB
- **总页数**: 293 页
- **PDF 类型**: 文本型（非扫描件）
- **OCR 需求**: 无需

### 2.5 内容质量深度检查

抽取第 15、50、100、150、200 页内容人工检查：

| 检查项 | 结果 |
|--------|------|
| 方剂名称（如"桂枝汤""麻黄汤""小柴胡汤"） | 正确提取 |
| 药材名称（如"桂枝""芍药""甘草""生姜""大枣"） | 正确提取 |
| 剂量信息（如"三两""半升"） | 正确提取 |
| 条辨编号（如"第1条""第12条"） | 正确提取 |
| 六经辨证术语（太阳/阳明/少阳/太阴/少阴/厥阴） | 正确提取 |

### 2.6 结论

**P0-1 风险消除。** qhsxzh.com 提供的倪海厦讲稿 PDF 是文本型而非扫描件，PyMuPDF 提取质量极佳，关键中医术语 100% 命中，乱码率仅 0.05%，无需 OCR。该系列还有针灸、内经、本草、金匮四本 PDF，格式一致，预期提取质量同等。

## 3. Day 2: 知识图谱查询验证

### 3.1 验证方法

1. 用 NetworkX 构建伤寒论 20 首方剂的迷你知识图谱
2. 设计 6 个查询测试用例覆盖典型查询模式
3. 量化查询延迟和正确率

### 3.2 图谱结构

| 维度 | 数值 |
|------|------|
| 总节点数 | 50 |
| 节点类型 | 3 类（方剂 20 + 药材 23 + 证型 7） |
| 总边数 | 116 |
| 边类型 | 2 类（方剂→药材、证型→方剂） |
| 图类型 | 有向图 |
| 持久化格式 | JSON |

### 3.3 查询测试结果

| 测试编号 | 查询内容 | 结果 | 耗时 |
|---------|---------|------|------|
| Q1 | 查询"桂枝汤"的组成药材 | PASS | <0.01ms |
| Q2 | 查询"麻黄汤"和"桂枝汤"的共同药材 | PASS | <0.01ms |
| Q3 | 查询"桂枝汤"和"麻黄汤"的药味差异 | PASS | <0.01ms |
| Q4 | 查询同时含"麻黄"和"桂枝"的所有方剂 | PASS | <0.01ms |
| Q5 | 查询"太阳病"证型对应的方剂 | PASS | <0.01ms |
| Q6 | 查询所有含有"甘草"的方剂 | PASS | <0.01ms |

**通过率: 6/6 (100%)**
**最大查询延迟: 0.01ms（目标 <100ms，超出 10000 倍）**

### 3.4 持久化测试

| 指标 | 数值 |
|------|------|
| JSON 序列化 | 即时 |
| JSON 反序列化 + 图谱重建 | 8.23ms |
| 内存占用 | 可忽略（50 节点级别） |

### 3.5 结论

**P0-2 风险消除。** NetworkX 内存图在 50 节点规模下查询延迟 0.01ms，远低于 100ms 目标。JSON 持久化加载 8.23ms，可接受。按规划图谱规模控制在 5000 节点以内，预期延迟仍在毫秒级。
